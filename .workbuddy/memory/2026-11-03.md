## 远端执行链路 SSH 有效性修复（18:35）
报错：部署 qwen3.8-27b 到 P40 报「建立 ssh 隧道：ssh 在隧道建立前退出（退出码255）stderr：（空）」。
真实原因（隧道日志 ~/Library/Logs/mangosteen/tunnel-11435.log）：`Connection to <ip>:23 closed by remote host`，认证已通过 → 错误文案把「远端执行阶段」故障错标成「隧道建立前」。
三个独立缺陷：
1) provision.rs:550 丢弃了 provision_resources 已验好的密钥，重新调 configure_ssh_access → 又跑一遍「重置root密码→装公钥→确认」；config 有 ssh_password 时密码被改，刚建立的密钥信任作废，后续全部连不上。改为直接复用 p.ssh。
2) 「隧道建成」≠「远端能执行命令」：隧道只是 ssh -L 本地转发，而 configure_node/下载的每条命令都新建连接。新增 confirm_remote_reachable(6次×2s) 在 configure_node 入口确认，失败以「节点配置环境/确认远端连接」报错。
3) 配了 log_dir 时 ssh stderr 只写 tunnel-<port>.log，管道为空 → 旧代码无条件读管道 → 恒显示「（空）」。新增 TunnelManager::diagnose：先管道、空则回读日志尾部（滤 known_hosts 噪音），三处失败分支统一用它。
原则：**stderr 报错必须能定位到真实原因**，不许出现「（空）」；**隧道建成后仍要确认远端可执行命令**再接长任务。

- ssh_exec 重试分类：仅 255+无真实 stderr 自动重试 3 次；认证失败/命令错误立即报错（SshFailure::Transient/Fatal）
- 轮询合并单连接（size/ok/state 一次取回）；连续 10 次失败才判死并提示断点保留
- base_opts 加 ServerAliveInterval=15/CountMax=4/TCPKeepAlive
- 发现存量问题：gateway e2e 一批用例在干净 HEAD 也失败（NoViableCandidate：本地不可行且无设备/云厂商），疑似 50401fe 引入的 preview 语义回归，待排查

## 第三轮：SSH 255 与 config.toml 损坏（重大发现）
- 用户报错命令是 `kill -0 $(cat ...ggdown.pid)` —— 属于下载启停的单次连接，走 ssh_exec
- **关键 bug**：ssh_exec 判「255 且 stderr 为空」才重试；但 Connection closed by remote host/refused 都有 stderr → 被判 Fatal 不重试。已改为「255 且未命中认证/配置类关键词即重试」，重试 5 次退避 1~4s，并加 ConnectionAttempts=5
- **更严重的独立发现**：~/Library/Application Support/mangosteen/config.toml 末尾残留半截 UTF-8（`...分配"""` + 孤立 `\x86\xe9\x85\x8d"""`），整个配置无法解析
  - 根因：atomic_write 临时名固定 `.<name>.tmp`，并发写（网关补全内置模板 + 用户保存模板）落到同一临时文件互相截断 → rename 出混合内容
  - 修复：唯一临时名(pid+seq+nanos) + 回读校验；加载时语法损坏→隔离为 .corrupt-<ts> 并回落内置默认（保证能启动），语义错误仍原样报错
  - 已备份并修复用户实际文件（3743→3731 字节），tomllib 校验通过，qwen3.8-27b 的 default/uncensored 模板均保留
- CLI 那两个 rejects_privileged_port 测试失败正是由这份损坏配置引起，修复后自动通过（不是代码缺陷）
