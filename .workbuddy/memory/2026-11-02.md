## 登陆方式为空根因：云API curl 继承死代理（20:47）
- 现象：两模型运行中但 UI 登陆方式为 "-"；ssh-info 返回 curl(7) Failed to connect 127.0.0.1:60922
- 根因：provider 两个 CurlTransport（compshare/transport.rs + drivers/curl.rs）都没禁用环境代理；守护进程从工具会话启动继承了 HTTP_PROXY=127.0.0.1:<临时端口>，会话结束代理死亡 → 部署时代理活着所以成功，之后所有云端 RPC（describe/库存/监控）全部失败。device/engine.rs 的 Ollama 探测同理
- 修复：①两个 CurlTransport build_args 显式加 --noproxy "*"（云厂商API直连，+2单测）②engine.rs Ollama list_models 加 --noproxy ③守护进程启动脚本剥离 HTTP_PROXY/HTTPS_PROXY/ALL_PROXY 并设 NO_PROXY=*（保护下载等其它链路）
- 顺带修：ssh-info 缓存键加 deployment_id 前缀——同节点多模型共享实例 ID，原键 provider:instance 会让第二个部署拿到第一个的缓存（deployment_id 标错）
- 验证：两部署 ssh-info 均 available=true、source=provider、deployment_id 各自正确
- 教训：长驻进程绝不能继承会话级临时代理；云端 API 类 curl 必须显式 --noproxy
